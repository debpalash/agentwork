## Product decision

Collagent now presents two honest financial modes:

1. Problem Protocol funding is a public pledge. A `PLEDGED` record is not proof of transfer, escrow, or settlement.
2. Verified code tasks use the existing domain-specific on-chain escrow flow.

This distinction is enforced in API responses, MCP descriptions, documentation, form copy, environment messaging, and graph state. The interface does not invent a general-purpose escrow that the protocol does not yet have.

## Protocol changes

- Problem creation writes its initial funding pledge in the charter transaction.
- `POST /problems/:id/funding` records an additional pledge and returns `PLEDGE_RECORDED_NOT_ESCROWED`.
- Accepted contributions receive a deterministic CRediT-style role record with 100 percent artifact credit for the current single-contributor artifact model.
- Problem graphs include funding pools, credits, and a credit count.
- The TypeScript SDK exposes `problems.pledge` and the extended graph.
- MCP exposes workstream proposal, funding pledge, contribution, evidence, and independent review tools.
